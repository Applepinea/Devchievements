# ADR-0018：扩展只做检测，判定与呈现留在桌面端

- **状态**：Accepted（产品负责人 2026-11-17 决定）
- **影响**：§36（Phase 3a Browser Only）的边界被收窄

## 决定

浏览器扩展**只负责检测** GitHub 活动；事件通过 Native Messaging 送到本地桌面应用，
由桌面应用用同一套 Rust 规则判定、入库、弹窗。

## 为什么

Browser Only 模式意味着浏览器里要有一份判定规则。规则在 Rust 核心里，
要让浏览器用上就得把引擎编译成 WASM 并暴露 ABI；
若不这样做而用 TypeScript 重写规则，两端必然分叉（ADR-0001 明确要避免）。

产品负责人选择了第三条路：**不让浏览器判定**。这样规则只有一份，
浏览器只是个探测器。

## 代价

- 扩展**不再能独立工作**：没有桌面应用时，它只能把检测结果存在本地，不解锁成就。
- 需要 Native Messaging 的注册（Host 清单 + 浏览器注册表项 + 固定扩展 ID）。
- Phase 3a 验收里「不依赖 Native Messaging」这一条**不再适用**。

## 保留的部分

- 检测规则（什么算可验证活动）仍在扩展里，且有单元测试。
- 扩展侧的 IndexedDB 仍然存在，作为桌面端不可达时的兜底，
  保证「检测到了但没送出去」不会丢。

## 一个具体的正确性要求

浏览器只接受**完整 40 位提交 id**。
短 id 无法与 hook 路径记录的全 id 去重，会导致同一个提交被计两次（§11.2）。
这条规则由测试固定住。
