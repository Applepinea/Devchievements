# ADR-0017：产品范围收敛为 Windows only

- **状态**：Accepted（由产品负责人在 2026-11-17 明确指示）
- **取代**：§29 中关于 macOS 与 Linux 的要求，以及兼容性矩阵里的对应列

## 背景

规范 §29 要求覆盖 Windows、macOS、Linux X11、Linux Wayland，并维护兼容性矩阵。

实际状况：

- 只有 Windows 被真实测过；其余列从项目开始就是「未验证」。
- CI 里的 macOS/Linux job 从未产出过有效信号：它们的失败全部来自
  只在 Windows 上被验证过的假设（路径、日期解析、文件权限）。
  每修一次，修的都是**测不到的平台上我们没打算发布的行为**。

产品负责人指示：从 2026-11-17 起只支持 Windows。

## 决定

1. **只支持 Windows**（10/11）。macOS 与 Linux 不在支持范围内。
2. CI 只跑 `windows-latest`。
3. 兼容性矩阵保留 macOS/Linux 列，但状态标为「不支持（产品决定）」，
   不再标「未验证」——一个是没测过，一个是不打算做，含义不同。
4. 现有 `#[cfg(not(windows))]` 分支**保留但不再维护**：
   删掉它们只会让非 Windows 构建以更晦涩的方式失败，留下来是诚实的。

## 后果

**变好的部分**

- CI 信号变干净：绿=Windows 上真的通过，红=真的坏了。
- 不再为没人用的平台付测试与修复成本。

**要接受的部分**

- 与规范 §29 不一致，这是**经授权的偏离**，不是遗漏。
- 若将来要支持其他平台，§29 的整张矩阵与降级链需要重新验证，
  不能因为代码里有 `cfg` 分支就认为「大概能跑」。

## 被删除的 CI job

`git-version-matrix`：它跑在 ubuntu 上，从不真的安装不同 Git 版本，
只打印一句警告。**打印警告不是覆盖率**，所以删掉而不是留着装样子。
多版本 Git 行为实验仍未实现，在 STATUS 里如实记录。
