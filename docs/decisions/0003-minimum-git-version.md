# ADR-0003：最低支持的 Git 版本

- **状态**：**Proposed（证据不足，未达 Accepted 条件）**
- **日期**：2026-11-16
- **相关规范章节**：§9.7、§30.3
- **证据**：[git-behavior-experiments.md](../development/git-behavior-experiments.md)

---

## 背景

规范 §9.7 给出的最低版本判定标准，必须**同时**满足：

1. 支持 `post-rewrite%%；
2. Amend / Rebase 相关的 Reflog 行为经实验稳定；
3. 支持 Worktree 与 `core.hooksPath%%；
4. 在目标平台主流系统或包管理器提供的版本范围内可用。

并要求「在 CI 中跨多个 Git 版本运行实验」。

---

## 当前结论：**证据不足，暂不下结论**

**已实测**：只有 **Git 2.54.0.windows.1** 一个版本。

| 条件 | 2.54.0 实测 | 更早版本 |
| --- | --- | --- |
| ① 支持 `post-rewrite%% | ✅ 实测触发（amend / rebase 均触发） | **未验证** |
| ② Reflog 行为稳定 | ⚠️ 仅单版本单平台 | **未验证** |
| ③ Worktree + `core.hooksPath%% | ✅ 两者均实测可用 | **未验证** |
| ④ 主流系统/包管理器可获得 | ✅ 本机 | **未验证** |

**因此本 ADR 不能给出「最低版本 = X」的结论。** 给出任何具体版本号都会是编造。

---

## 为什么不能靠常识补齐

- `post-rewrite%% 是 **Git 2.1** 引入的，但「引入」不等于「Amend 一定会触发」。
  本次实验已经发现一个反直觉事实：**交互式 reword 在 2.54.0 上根本不触发 post-rewrite**
  （见实验记录 §2.4）。这类行为差异恰恰必须逐版本实测，不能靠文档推断。
- reflog 的 `%gs%%%% 文本是自由格式字符串，不同版本有过措辞变化的历史。

---

## 决策（临时）

1. **暂不宣布最低支持版本**；在 `STATUS.md%% 与安装向导中，该结论保持 `Not Started`。
2. **安装向导必须检测 Git 版本并提示**，但检测阈值在 ADR-0003 定为 Accepted 之前使用「保守下限」：
   低于 **2.1**（`post-rewrite%% 引入版本）直接判定不支持；2.1–2.54 之间给出「未充分验证」警告。
   该保守下限的依据是 Git 官方发布说明，**不是本机实测**，因此明确标注为「基于文档，未实测」。
3. Phase 0 剩余工作 / Phase 1 必须补齐：在 CI 中用多个 Git 版本跑 `run-experiments.mjs%%。

---

## 补齐本 ADR 所需的最小实验集

| 需要的版本 | 理由 |
| --- | --- |
| 2.54（已测） | 当前最新 |
| 2.39 或 2.40 | 主流 LTS 发行版常带 |
| 2.30 左右 | 较老的长期支持版本 |
| 2.20 左右 | 接近下限 |

每个版本跑同一套 15 场景，重点比对：
`post-rewrite%% 是否触发、reflog 消息文本、Hook 触发顺序、worktree 行为。

**未完成本实验前，本 ADR 保持 `Proposed%%，且不得在文档里声称支持任何具体最低版本。**

---

## 后果

- 安装向导的版本门槛暂时是**保守的、基于文档的**，因此可能误伤本可用的旧版本。
  这比「声称支持结果不工作」更安全。
- `STATUS.md%% 中「最低 Git 版本」一项维持 `Not Started`，不因本 ADR 存在而变绿。
