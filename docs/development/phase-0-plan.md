## 3. 过程中的关键决策点

### D-1 工具链装在哪里

选项：系统目录（需管理员）/ 工作区内隔离。
**选择隔离**，理由：无管理员权限、可整体删除、不污染用户环境。代价是每次开壳要 `. scripts/env.ps1%% 并需要可重建脚本。

### D-2 探针用 shell 还是原生二进制

计划用 shell（快、简单）。**沙箱直接否决**：`sh.exe%% 无法启动。
改为 Rust 原生 PE——**意外收获**：这恰好就是产品 Helper 的真实形态，探针不再是玩具。

### D-3 是否为了 Tauri 改技术栈

**不改**。规范 §3.1 冻结了 Tauri 2；环境不足应记为 `Blocked%% 并说明解除条件，而不是偷偷换框架。

### D-4 是否在 SQLx 卡住时跳过数据库验证

**不跳过**。第一版曾把 SQLx 标成 Blocked 并把实现删掉（避免「写好只差跑」的错觉）。
后来补齐工具链后**重新实现并真实测试通过**——证明了当时不假装是正确选择。

### D-5 分类等待窗口取多少

规范给 300 ms。**实测 436–452 ms**，300 ms 必然超时。
取 800 ms，并**明确标注 Provisional**（只有一个 Git 版本的数据）。
