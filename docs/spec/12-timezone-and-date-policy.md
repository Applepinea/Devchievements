# 12. 时区与日期策略

- 支持 IANA Time Zone：UTC 时间、本地日期、夏令时、时区变化、每日统计周期、用户自定义日界线。
- 默认使用用户本地时区；默认每日开始时间 `00:00`，用户可调整（如 04:00、06:00 或自定义）。
- 必须保存事件发生时使用的时区与日期策略；`local_date` 在事件入库时确定。
- 修改时区或每日开始时间时，必须询问用户是否重算历史投影；不得无提示地改变既有统计或成就解锁时间。
- 必须处理：软件跨午夜运行、休眠恢复、系统时间调整；不得只在进程启动时计算一次日期。

**边界规则**

- `local_date` 在事件入库时，按事件时间、当时配置的 IANA 时区和当时的日界线计算并固定保存；之后修改系统时区或跨时区旅行，不改变既有事件的 `local_date`。
- 新事件使用当前配置的时区。旅行或改时区后，连续活跃天数按 `local_date` 去重计算，允许出现重叠或空缺，并在统计页给出提示。
- 日界线为 04:00 时，00:00–03:59 的事件归属前一天；修改日界线按上文规则询问是否重算历史。
- 历史导入默认使用用户配置的 IANA 时区（而不是 Commit 记录的时区偏移）和当时的日界线计算 `local_date`，并把原始偏移保存在 payload 中便于追溯；导入选项中提供「按 Commit 记录的时区」作为显式选择。
- 夏令时导致日界线落在不存在或重复的本地时间时，使用时区库的标准解析规则，并有测试覆盖。
- Phase 1 增加时区属性测试：对任意事件序列和时区切换，`local_date` 确定且不随重放改变；同一事件重复入库结果不变。
