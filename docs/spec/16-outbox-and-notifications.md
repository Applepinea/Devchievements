# 16. Outbox 与通知架构

## 16.1 核心原则

Engine 不直接执行通知。事件持久化、统计投影、成就解锁结果和 Outbox 通知意图必须在同一数据库事务中提交。

- Desktop：SQLite Outbox。
- Browser Only：IndexedDB Outbox。
- Full Experience：Companion 是唯一 Outbox 权威。

## 16.2 Outbox 字段

至少包含：`notification_id`、`event_id`、`status`、`owner_channel`、`claimer_id`、`offer_deadline`、`created_at`、`attempts`、`last_error`、`processed_at`。`status` 取值见「通知所有权协议」的状态表。

外部通知副作用不能保证严格 exactly-once，必须通过幂等 ID、状态机、重试和恢复机制尽可能避免重复展示。

## 16.3 新鲜度策略

事件年龄从事件的真实发生时间（如 Hook 触发时间）算起：

| 事件年龄 | 行为 |
| --- | --- |
| 0–10 分钟 | 正常通知 + 音效 |
| 10 分钟–24 小时 | 汇总通知 |
| 超过 24 小时 | 静默更新统计 |

用户可以调整。以下情况默认静默：历史导入、历史回填、事件重放、统计重建。事件过期不代表事件无效，仍参与合法统计和成就判断。

## 16.4 通知默认行为表

| 事件 | 默认行为 |
| --- | --- |
| 普通 Commit | 轻提示音，不弹完整通知 |
| 每日等级升级（Common 至 Legendary） | 完整弹窗 |
| 永久成就解锁 | 完整弹窗 |
| 多项同时解锁 | 合并弹窗 |
| 历史导入 / 回填 / 统计重建 | 静默（导入完成可选一条汇总） |
| Queued 事件 | 轻量状态反馈 |
| 过期事件 | 静默或汇总 |

## 16.5 Queued 事件

Companion 离线时，扩展可以持久化事件：

- 默认最大 1000 条或 10 MB（先到者为准），保留 7 天，均可配置。
- 超过限制时明确提示，不得静默丢弃；事件过期不代表事件无效。
- 反馈文案示例：「已记录，等待 Companion 启动」。
- Queued 状态下不正式解锁成就、不发送正式成就通知，等待 Companion 恢复后最终仲裁。

## 16.6 通知队列

支持排队；高稀有度优先；相同事件合并；避免短时间连续弹窗；用户可关闭普通 Commit 通知；遵循系统勿扰设置；队列持久化，崩溃后可恢复。

**合并规则与示例**

- 同一事件触发多项奖励时合并为一个弹窗：主标题取最高稀有度的一项，其余在副行列出（最多 3 项，其余显示「+N」）；同稀有度时永久成就优先于每日里程碑；音效取主项音效，不叠加播放。
- 示例：首次 Commit 同时触发 First Commit（Common）与每日 Common，合并为一条弹窗；同一事件触发 Epic 永久成就与 Rare 每日升级时，以 Epic 为主，Rare 作为副行。
