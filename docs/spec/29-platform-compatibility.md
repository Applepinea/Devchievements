# 29. 平台兼容性与降级

## 29.1 总原则

- 启动时探测平台能力，按降级链选择展示方式：桌面浮窗 → 系统通知 → 仅应用内提示（图鉴新解锁标记）。
- 不得假设所有平台、桌面环境和合成器具备相同的窗口能力，不得声称能绕过操作系统的全屏或通知限制。
- 每项能力在兼容性矩阵中只能有以下状态之一：原生支持、部分支持、需要桌面环境特定实现、仅能降级为系统通知、未验证。
- 当前环境无法测试的平台，一律标记为未验证，并在 CI 中至少完成构建验证。

## 29.2 Windows

不抢占前台焦点；不拦截鼠标输入（点击穿透）；每显示器 DPI 缩放正确；独占全屏应用之上可能无法显示浮窗，必须降级为系统通知；遵循专注助手（勿扰）设置。

## 29.3 macOS

适配 Spaces 与全屏应用；不干扰当前工作空间；遵循专注模式；通知权限请求与说明；签名与公证影响首次运行体验。

## 29.4 Linux

- X11：置顶、透明、点击穿透、不抢焦点。
- Wayland：不同合成器对浮窗、置顶、定位的支持差异很大，必须分 GNOME、KDE Plasma 及其他实际测试过的环境记录，不得假设一致。
- 评估 Tauri / WebKitGTK 的透明窗口性能与兼容性；无法可靠实现时降级为系统通知。
- 部分桌面环境默认没有系统托盘，必须提供无托盘时的替代入口（主窗口、应用内开关）。

## 29.5 通用能力

多显示器（可选择弹窗所在屏幕）；DPI 缩放；系统勿扰；减少动态效果；高对比度与基本辅助功能；稀有度不得只靠颜色区分（同时使用文字或图形）。

**全屏应用运行时**：提供设置项，可选「降级为系统通知」「延后到退出全屏」「静默并在图鉴显示徽标」。默认降级为系统通知，平台不支持时静默并显示徽标；延后的通知仍受新鲜度策略约束。

## 29.6 兼容性矩阵

在 `docs/development/platform-matrix.md` 维护矩阵。列：Windows 10 / 11、macOS、Linux X11、Linux Wayland（按桌面环境细分）、Chrome、Edge、Brave。行：无边框透明浮窗、不抢焦点、点击穿透、置顶、全屏应用上方显示、系统托盘、系统通知、勿扰检测、多显示器、DPI、安装与卸载、Hook 行为、Native Messaging、WASM。初始全部为「未验证」，随实测更新。

每个 Phase 结束时必须更新当前可测平台的状态，并在 `STATUS.md` 中引用。
