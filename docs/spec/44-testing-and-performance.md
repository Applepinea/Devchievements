# 44. 测试与性能目标

## 44.1 性能目标

以下是目标，不是已经实现的事实：

| 项目 | 目标 |
| --- | --: |
| Git Hook p95 执行时间 | < 50 ms |
| Companion 在线 Commit 到通知 p95（已分类事件，不含分类等待窗口） | < 500 ms |
| 重复统计 | 0 |
| 已持久化事件丢失 | 0 |
| 空闲 CPU 占用 | < 1% |

Full Experience 下，Offer deadline 计入 500 ms 预算。

## 44.2 测试原则

性能目标必须使用真实样本验证。报告必须说明测试设备、操作系统、样本数量、测量方法、p50 / p95、已知误差。不得编造测试数据；没有实测的指标标记为未验证。

## 44.3 可靠性测试

并发 Hook；Spool 损坏；IPC 失败与回退；数据库中断；Companion 崩溃；事件重复；Outbox 重试；通知 ACK 丢失；浏览器 Service Worker 回收；离线恢复；卸载恢复；Hook 事件序列回放（trace fixtures）。

## 44.4 性能测量方法

- Hook 耗时：从 Git 调用 Hook 的时刻到 Hook 进程退出，包含进程启动和 Helper 工作，由外层测量脚本打点。
- Commit 到通知：起点为 Git 调用 Hook 的时刻，终点为弹窗首帧渲染或提示音开始播放。
- p95 目标针对 Companion 已在运行的热启动；冷启动单独报告，不计入目标。
- 每项至少 200 个样本，并记录设备、操作系统、Git 版本和测量脚本。
